# SC14448-E4.2 — queue tag provenance and parser reachability

**Result:** no resolved direct allocator caller supplies tag `0x23` at entry
under the bounded register/CFG model. This is **not** a proof that the parser
branch is globally unreachable. All evidence is static, offline, image-SHA
checked and independently regenerated by `tools/cr16_queue_provenance.py`.
Six reports (`tools/reports/cr16-e42-*.json`) retain raw instruction bytes,
reverse def-use paths and unresolved aliases.

| Image | allocator | direct calls | `0x23` excluded at allocator entry under model | unknown tag source | direct parser call |
|---|---:|---:|---:|---:|---:|
| normal | `0x386A` | 22 | 21 | 1 (`0x393A`, wrapper argument) | `0x39F2` |
| p2test | `0x26F7C` | 19 | 18 | 1 (`0x2704C`, wrapper argument) | `0x2710C` |

P2test's five callers following `call 0x2327A` were unresolved in E4.1's
adjacent-instruction scan; the locally checked three-instruction leaf sets
`r2=0x14` before returning. The two wrapper arguments remain unknown:
`0x3934`/`0x27046` preserve incoming `r2`, and their direct callers include
stack-payload wrappers with caller-supplied tags; no complete interprocedural
value bound excludes `0x23`. Unknown indirect callers/aliases remain possible.
Classification `TAG_23_EXCLUDED_UNDER_MODEL` applies **only to `r2` at the
listed direct call**, not to any later header value or parser branch.

The critical E4.1 distinction is **state vs tag**. Case-7 helper `0x9E10` /
`0x27412` passes tag `0x22` into allocator; after return it computes
`payload−2 = item+2` and stores `0x23` there. It builds payload word
`0xFFF1` and subtype `8`. It does **not** set `item+3` to `0x23` on this
checked path. Main copies `item+3` into global `0x93CB`/`0x9512` and
dispatcher separately may set that global to `0x23`, not the header.
The parser's `0x23` comparison reads `item+3` itself. Therefore **case 7 →
new subtype-8 item → same parser command branch is unproved**, even though
case 7 really creates a queue item. Subtype 8 is not one of the parser's
named selected cases; its processing is unknown.

The selected queue-to-dispatch-to-parser **call chain** remains directly
verified, but a particular producer generation reaching `0x23` tag check
does not. The `0x0167` branch and `0xFFF1` cases are conditional on this
unproved tag and on available payload. No source for a *parser-reachable*
item of either type was established. Header aliases, memcpy/overlap, DMA,
interrupt writers, wraparound reuse, indirect entries and call effects
remain open; nothing here proves absence of a real host interface.

E4.3 must separate **conditional handler effects** from **producer-backed
runtime effects**. E4.4 must not infer a transport from the parser's field
comparisons. No FON priority change; K1/K2 remain NO-GO.
