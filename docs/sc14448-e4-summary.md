# SC14448-E4 — bounded offline firmware architecture

**Result:** a reproducible P0/P1 architecture map, not a complete firmware
protocol. Generated by `tools/cr16_architecture.py` from SHA256-checked
normal/p2test firmware, revalidating all 31 vector raw entries. Nine reports
are in `tools/reports/cr16-e4-*.json`. No firmware or hardware execution.

| Feature | normal | p2test | Proof limit |
|---|---:|---:|---|
| direct-call/vector/main function candidates | 431 | 403 | branch targets are not function seeds |
| closed *local* CFG/prologue/return regions | 141 | 146 | not global entry coverage |
| overlapping function candidates | 25 | 19 | preserve overlaps rather than invent boundaries |
| uniquely paired 12-insn structural prefixes | 97 | 97 | similarity ≠ semantic identity |
| second-level static start | `0x15AA` | `0x1026` (setup `0x102C`) | loader handoff static; no runtime observation |
| main-loop entry | `0x39F8` | `0x27112` | linked by known startup call path |
| queue dispatch entry | `0x39D6` | `0x270E8` | called from selected main loop branch |
| command-item parser | `0x9E68` | `0x2746A` | input is queue item, not proven UART RX |
| UART TX pump | `0x9F84` | `0x9BC8` | writes effective `0x00FF4902` |

The 97 matches are only *unique prefix candidates*. Separately verified
parser and TX counterparts have the same selected comparisons and register
effects in both images. Different addresses are not different semantics.

**UART boundary:** in second-level vectors 20 and 21 both point to the same
`nop; retx` stub (`0x28DCA` / `0x9FFC`); these vector indices are UART RX/TX
*names from a related chip*, not an SC14448 source identity. Second-level
TX uses byte buffer, index cells `0x9376/78/7A` or `0x94AE/B0/B2`, writes
`0x00FF4902`, acknowledges at `0x00FF4904`, tests bit5 at `0x00FF4900`.
The earlier first-level UART boot receiver and its handshake are distinct;
their framing is **not** assigned to runtime. No second-level UART RX→parser
source chain is established.

**Selected inbound route:** main loop compares queue pointer slots `[0xDA]`
and `[0xDE]`, calls an item dispatcher (`0x3ABE`/`0x271DC`), which calls
parser (`0x39F2`/`0x2710C`). Parser tests a byte against `0x23` and a word
against `0x0167` or `0xFFF1`. For `0xFFF1`, it compares the byte at +2 to
`7`, `9`, `10`, `13`; these are *numeric IDs*, not named commands. One
selected branch writes a word through a payload-supplied pointer, others
call helpers. Packet length, validation, queue producer and responses are
unresolved; a checked marker `0x23` is **not** proof of UART synchronization.

**Subsystem graph:** only checked direct edges main→dispatcher→parser,
main→TX and TX→architectural `0x00FF4902` are included. DIP/DSP handlers
and their E3.3/E3.4 helper paths have verified vectors, but no invented
UART→DSP/DIP/PCM or FON link. Selected queue/RAM cells and all vector
addresses are listed, without claiming every shared cell is a mailbox.

Three key blockers: (1) host ingress/queue producer is unproved while
UART RX vectors are stubs; (2) parser input length/complete handler and
response semantics are unclosed; (3) indirect aliases, asynchronous paths
and physical PCM/analog side effects have no source-to-sink proof.
Q46/Q55/Q75 remain open. K1/K2 remain NO-GO; no hardware action.
