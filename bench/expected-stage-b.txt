FON probe-only ready; no MMIO/clock/reset/IRQ/DMA access

IRQ terminology
---------------
raw DT GIC SPI      156 / 159        (what the DTS node contains)
GIC INTID           188 / 191        (SPI + 32)
Linux virq          not requested in probe-only;
                    diagnostics prints irq=-1
The Linux virq is created only by full-mode platform_get_irq_optional();
it may not exist at all in probe-only.  Do not substitute 188 for an
unknown runtime virq.

The register fields remain zero because no diag_refresh was issued.

/proc/interrupts
----------------
It changes naturally between snapshots (counters).  Byte-for-byte equality is
NOT a pass criterion.  Probe-only does not request an IRQ.

/proc/iomem
-----------
Probe-only does not call devm_ioremap_resource().  A FON range appearing in
/proc/iomem is an error.  Equality proves only that no new visible claim was
added; it does not prove the absence of all hardware accesses.

kprobe/module params
--------------------
probe_only=1 is recorded in preflight.txt/modinfo.txt.
